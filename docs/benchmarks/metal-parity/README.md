## Method, reproduction and limits

Read [coverage.md](coverage.md) for every requested category/tool, [source-evidence.md](source-evidence.md) for exact implementation evidence, and [measurements.md](measurements.md) for bounded timing/memory observations.

Built isolated Python 3.13.12 environment with PySide6 6.11.3, NumPy 2.5.4 and both native crates in **release** using worktree-local `.cargo-work`; render uses `extension-module` and `CARGO_PROFILE_RELEASE_STRIP=none`. Build logs: [core](raw/build-core.log), [renderer](raw/build-render.log), [pip](raw/setup.log). No `target/debug` created. No full suite.

The original `--capture-only` still showed windows. The audit extends it to use an explicit `QOpenGLContext`/`QOffscreenSurface` and the existing Metal offscreen API on an unshown native host. `--live-frame` executes ordinary GL/Metal draw passes with injected state: GL's painter target is redirected to the captured QImage; Metal calls `render(False)` and capture readback. Neither window is mapped; no main app, AppleScript, screen capture or input automation was used. This is a controlled renderer experiment, not actual OS interaction.

GL requires an initialization/warmup draw before a stable comparison. First exploratory captures exposed incomplete first-pass initialization (missing image plane/incorrect section clip). They were replaced by the corrected warmed captures and are excluded from the final evidence. Final model/case JSON records `gl_first_capture_seconds`. Ride was loaded/captured exactly twice in total, both within 300 s, and final warmed evidence replaces the first pair.

```sh
# From this worktree root. Every process is bounded.
timeout 60 env PYTHONPATH=. QT_QPA_PLATFORM=offscreen .venv-work/bin/python docs/benchmarks/metal-parity/fixture.py
timeout 90 .venv-work/bin/python scripts/wgpu_look_compare.py docs/benchmarks/metal-parity/synthetic.igz --capture-only --live-frame --audit-case selected-face --output docs/benchmarks/metal-parity/raw
timeout 30 env PYTHONPATH=. QT_QPA_PLATFORM=offscreen .venv-work/bin/python docs/benchmarks/metal-parity/probe.py
timeout 180 env QT_QPA_PLATFORM=offscreen .venv-work/bin/python docs/benchmarks/metal-parity/make_crops.py
```

Exact capture argv, timeouts/return codes: [models](raw/runs-models.json), [synthetic](raw/runs-synthetic.json), [extra](raw/runs-extra.json), [live extra](raw/runs-live-extra.json), [additional](raw/runs-additional.json). `fixture.extras()` creates the separate figure/smooth/alpha documents. All supplied `.igz` files were read-only; texture extraction for capture uses worktree `.look-tmp`.

All final capture stderr was reviewed. Successful GPU captures emit the same first-frame GL sampler warning (`GLD_TEXTURE_INDEX_2D ... unloadable`); warmed reference images are visibly populated. Two intentional billboard export probes throw G09. Their teardown emits secondary GL-context destruction warnings; these are harness cleanup fallout, not separate product bugs. Early harness errors were fixed and rerun. CPU-only probe logs include Qt offscreen-widget/font warnings. The installed app and its logs were not used, so unrelated user-session errors cannot contaminate this audit.

**Not tested:** real menu presentation, Space/global shortcuts under actual focus, physical pinch/two-finger preferences, live resize/dock/tab switching, native tooltips, OS file drag/drop, sustained flicker, end-to-end presented first-frame time, actual A3 composer UI, arbitrary scene-transition animation, exhaustive VCB/modifier/undo-during-preview matrix, complex mesh scale figure, geographic imagery/DEM/photo-mesh raster fixture, >1024 texture chart, 2× physical backing scale, or near/far clipping stress. These require additional fixtures or controlled native-session acceptance; the no-screen-takeover audit does not establish them. They are explicitly open rather than marked same. The fixture contains no fog/watermark because neither is available in the reference renderer.
